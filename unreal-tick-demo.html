BeginPlay vs Tick

Every Unreal actor has a lifecycle. BeginPlay fires once. Tick fires every frame, forever, until something stops it. Spawn an actor below and watch the event timeline tell the story.

What you're watching

  • BeginPlay runs ONCE when the actor is fully in the level. Do your initial setup here, not in the constructor.
  • Tick runs EVERY frame. Keep it lean. It's the easiest place to nuke your frame rate.
  • Tick can be disabled for static actors with PrimaryActorTick.bCanEverTick = false;. Forgetting this is the #1 reason Tick "doesn't fire".
  • The constructor runs in the editor too. BeginPlay only runs at play time. That difference confuses every newcomer once.
Show me the Unreal C++ 
AMyActor::AMyActor()
{
    // Constructor runs in editor AND at runtime.
    // Forget this line and Tick is silent forever.
    PrimaryActorTick.bCanEverTick = true;
}

void AMyActor::BeginPlay()
{
    Super::BeginPlay();
    UE_LOG(LogTemp, Warning, TEXT("BeginPlay fired once."));
    // initial state setup goes here
}

void AMyActor::Tick(float DeltaTime)
{
    Super::Tick(DeltaTime);
    // runs every frame — keep this lean
}

void AMyActor::EndPlay(const EEndPlayReason::Type Reason)
{
    Super::EndPlay(Reason);
    // cleanup, save state, etc.
}
